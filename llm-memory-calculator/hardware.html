How the pieces connect

Three different questions, each answered by a different knob. Mixing them up is where the confusion comes from.

1 · Instance need

Weights plus KV cache plus fixed state, from page 1. Only the model, context, users and fill change it. Divide by 0.92 and round up to a catalog class: 32, 48, 64 or 96 GB.

2 · NUMA node budget

Run one vLLM instance per NUMA node, users split between them. vLLM reserves 92% of its node's memory at startup, whatever the instance needs; the OS keeps the rest. The instance must fit inside that 92%.

3 · Host DIMMs

Every memory channel gets one DIMM, because decode speed is set by memory bandwidth. The DIMM count is fixed by the processor (sockets × channels); the DIMM size only buys capacity. MRDIMM raises bandwidth, which raises tokens per second.

Why bandwidth sets speed

Each new token reads all the weights from memory once. So one user can't go faster than bandwidth ÷ weight size. Real speed lands below this ceiling, but it moves with it.

Where the numbers come from

  • Every processor figure (cores, TDP, memory types and speeds, memory channels per socket, and how many sockets it supports) comes from that SKU's specifications page on Intel ARK, checked on 27 November 2026. Each card above links to its page. Only P-core SKUs are listed, because AMX, the matrix engine vLLM uses for BF16, is on P-cores.
  • The 92% reservation per NUMA node: Intel Inference Microservices, Environment variables. Memory classes: Supported Intel platforms.
  • Peak bandwidth per socket = channels × 8 bytes × transfer rate. It's the theoretical peak; measured bandwidth is lower.
  • Why bandwidth sets speed: Intel describes LLM inference on Xeon as "a memory-bound workload", with memory reads as the largest hot spot (Boost LLMs with PyTorch on Intel Xeon). The ceiling on this page (bandwidth ÷ weight size, one user) is the arithmetic that follows from that: each new token reads every weight once.
  • For scale, Intel's own measurement: two Xeon 6980P with 24 × 96 GB MRDIMM-8800 served Llama 3.1 8B at 1,139.51 tokens per second in MLPerf Inference v6.1, Server scenario, CPU only (Intel newsroom, September 2026). That is total throughput across all users, not one user's speed. For a measured figure on a specific SKU and model, use Intel's On-prem AI Performance Advisor.
  • One vLLM instance per NUMA node follows Intel's vLLM on Xeon guide, which keeps each model copy on local memory. Which sub-NUMA modes a server offers depends on the processor and the BIOS; the selector here is for exploring, not a statement of what each SKU supports.
  • Model numbers and the KV cache formula are the same as on page 1. All figures are planning estimates: measure with real prompts before setting limits.
